Nextcloud 文件分享审批工作流插件说明
1. 项目说明
本插件为 Nextcloud Webhooks 插件的二次开发版本，在保留原插件 Webhook 能力的基础上，新增了 文件分享审批工作流 与 文件下载审批工作流 功能。
新增功能主要面向企业内部敏感文件外发和下载管控场景：当用户发起文件分享或下载时，系统可根据管理员配置的 Workflow 规则判断是否需要审批；命中规则后，分享或下载会被审批流程接管，审批通过后才允许继续执行，从而实现“分享前审批”和“下载前审批”。
本版本不是重写插件，也不是替换原插件功能，而是在原插件基础上进行增量扩展。

5. 新增功能概览
5.1 文件分享审批
当用户发起文件分享时，插件会监听分享创建前事件。如果管理员配置了对应 Workflow 规则，并且当前分享命中规则，插件会：
记录一条待审批记录。
阻断原始分享创建。
给审批人发送 Nextcloud 原生通知。
审批通过后，由插件按原分享信息重新创建分享。
审批拒绝后，不创建分享。
5.2 文件下载审批
当用户下载文件时，插件会根据 Workflow 规则判断是否需要审批。命中规则后，下载会被拦截，并向审批人发送审批通知。
下载审批支持以下场景：
Web 文件列表下载
WebDAV 文件读取 / 下载
直接下载链接场景
文件夹或多文件打包下载场景
下载审批通过后，用户需要重新点击下载。系统会根据审批人设置的下载次数和有效期判断是否放行。
5.3 触发动作多选
审批配置中新增“审批触发动作”，支持多选：
触发动作	说明
文件被分享	用户发起分享时进入审批判断
文件被下载	用户下载文件时进入审批判断
管理员可以配置：
只审批分享
只审批下载
同一条规则同时审批分享和下载
5.4 支持内部用户分享与公开链接分享
插件支持常见分享类型，包括：
用户分享
群组分享
公开链接分享
其他 Nextcloud 标准分享类型的基础字段保存与恢复
公开链接如果涉及强制密码策略，需要以实际 Nextcloud 策略为准。插件会尽量恢复可读取的分享字段。
5.5 多人审批
Workflow 配置中可以选择一个或多个审批人。
审批人会收到 Nextcloud 通知，可在 Web 控制台或客户端通知中处理审批。
5.6 审批策略
支持两种审批策略：
策略	说明
或签	任意一名审批人同意即通过
会签	所有审批人同意后才通过
只要任一审批人拒绝，审批流程即视为拒绝。
5.7 下载次数和有效期授权
下载审批通过时，审批人可以设置：
授权项	说明
允许下载次数	用户在审批通过后最多可下载几次，默认 1 次
下载有效期	审批通过后的有效时间，超过后需要重新申请
规则说明：
下载审批通过后不会自动下载文件。
用户需要重新点击下载。
每次放行下载会消耗 1 次授权次数。
超过下载次数后，再次下载会重新触发审批。
超过有效期后，再次下载会重新触发审批。
同一用户、同一文件、同一审批规则的授权独立计算。
5.8 同一文件 30 秒内防重复审批
为避免用户连续点击导致审批通知重复发送，本版本增加了防重复申请机制：
场景	规则
分享审批	同一用户、同一文件、同一 Workflow，30 秒内只创建一条审批
下载审批	同一用户、同一文件、同一 Workflow，30 秒内只创建一条审批
30 秒内重复触发时，系统不会重复创建审批记录，也不会重复发送审批通知。
5.9 文件夹过滤
管理员可以在 Workflow 中配置审批范围：
范围	说明
全部文件夹	所有文件分享 / 下载均进入审批判断
仅指定文件夹内	只有选定文件夹内的文件才进入审批
排除指定文件夹	选定文件夹外的文件才进入审批
配置页提供文件夹搜索能力，方便管理员选择路径。
5.10 保留原始 Workflow 筛选条件
本版本在新增文件审批能力后，保留并补充原始 Webhooks / Workflow 常用筛选条件，避免新增审批实体后丢失原来的过滤能力。
支持的筛选条件包括：
筛选条件	说明
文件夹路径	按文件所在路径筛选
文件名	按文件名精确匹配、包含、不包含等方式筛选
文件类型 / MIME Type	按 MIME Type 或文件类型筛选
文件系统标签	按 Nextcloud 系统标签筛选
Workflow 原有条件	尽量兼容原插件和 Workflow Engine 可用的筛选条件
其中，文件系统标签支持搜索选择，便于管理员快速配置标签规则。
5.11 动态记录

6. 审批流程说明
6.1 分享审批流程
用户在 Nextcloud 中对文件或文件夹发起分享。
Workflow Engine 判断本次分享是否命中审批规则。
如果命中审批规则，插件阻断原始分享。
插件记录审批单并通知审批人。
审批人同意或拒绝。
审批通过后，插件按原始分享参数重新创建分享。
审批拒绝后，不创建分享。
6.2 下载审批流程
用户点击下载文件。
Workflow Engine 判断本次下载是否命中审批规则。
如果命中审批规则，插件阻断下载。
插件记录审批单并通知审批人。
审批人点击“同意并设置下载权限”。
审批人在授权页设置下载次数和有效期。
审批通过后，用户重新点击下载。
系统判断授权是否有效：
在有效期内；
剩余下载次数大于 0。
满足条件则放行下载并扣减次数。
授权过期或次数用完后，再次下载需要重新审批。
6.3 Workflow Engine 判断规则
Nextcloud Workflow Engine 根据管理员配置判断是否命中审批规则。
判断维度包括：
当前触发动作是否在配置的“审批触发动作”中；
文件路径是否符合配置范围；
文件名是否符合规则；
文件类型 / MIME Type 是否符合规则；
文件系统标签是否符合规则；
是否配置了审批人；
是否满足其他 Workflow 条件。
6.4 拦截原始分享或下载
如果命中审批规则，插件会在动作真正完成前阻断原始操作。
分享场景中，用户可能看到：
```text
分享申请已提交审批，审批通过后文件才会真正分享。
```
下载场景中，用户可能看到：
```text
下载申请已提交审批，审批通过后请重新下载文件。
```
这属于正常行为，表示原始动作已经被审批流程接管。
6.5 审批通知
插件会向审批人发送 Nextcloud 原生通知。
通知中包含：
申请人
申请动作
分享
下载
文件名称
审批操作按钮
同意
拒绝
同意并设置下载权限
6.6 审批处理
审批人可以在以下位置处理审批：
Nextcloud Web 顶部通知栏
Nextcloud 桌面客户端通知
Nextcloud 移动端通知
Web 端可直接操作；客户端侧为了兼容不同客户端行为，审批按钮会打开浏览器处理审批，并显示中文审批结果页或授权页。
6.7 审批通过
分享审批通过后，插件会按原始分享参数重新创建分享。
下载审批通过后，插件会创建下载授权，用户重新点击下载时按授权次数和有效期放行。
6.8 审批拒绝
审批拒绝后：
分享审批不会恢复创建分享；
下载审批不会创建下载授权；
系统会通知申请人审批被拒绝。

指定文件夹路径

8. 安装与升级
8.1 全量替换部署
推荐使用全量替换方式部署：
```bash
cd /var/www/html

sudo -u www-data php occ app:disable webhooks
rm -rf custom_apps/webhooks

cd custom_apps
tar -xzf /path/to/nextcloud-webhooks-share-approval-additive-0.7.0-ui-redesign.tar.gz

cd /var/www/html
sudo -u www-data php occ app:enable webhooks
sudo -u www-data php occ maintenance:repair
sudo -u www-data php occ maintenance:mode --off
```
如环境需要执行升级命令，可再执行：
```bash
sudo -u www-data php occ upgrade
```

升级后建议在浏览器中强制刷新：
```text
Ctrl + F5
```
如果通知中仍显示旧按钮或旧内容，建议清理旧通知后重新发起一次审批测试。

13. 性能与防重复优化说明
本版本对新增审批逻辑做了轻量性能优化：
审批记录创建后，尽量复用内存中的审批数据，减少重复数据库查询。
多审批人通知使用批量发送 / 批量刷新方式，减少通知推送往返。
审批完成后，通知清理与结果通知合并处理。
`Notifier::prepare()` 增加请求级审批记录缓存，避免通知列表刷新时重复读取同一条审批记录。
分享字段序列化减少重复 getter 调用。
仅在命中审批 Workflow 规则时进入审批逻辑，避免影响未配置审批的普通分享 / 下载。
原 Webhook 功能逻辑保持独立，避免审批逻辑影响原 Webhook 事件发送。

15. 注意事项
本插件适配 Nextcloud 32，其他版本需要重新验证。
由于本插件保留原 App ID `webhooks`，部署时应替换原插件目录，不要同时安装两个同名 app。
如果公开链接分享启用了强制密码、强制过期时间等系统策略，审批通过后的分享恢复仍会受到 Nextcloud 原生分享策略影响。
如果客户端显示旧通知按钮，建议清理旧通知后重新发起审批流程测试。
如果变更了域名、反向代理、HTTPS 配置，需要确认 Nextcloud 的 `overwrite.cli.url`、`trusted_domains` 等配置正确。
原插件许可证为 AGPL，二次开发和分发需遵守对应开源许可证要求。
下载审批通过后不会自动继续下载，用户需要重新点击下载。
下载授权以用户、文件、审批规则为维度计算，授权次数和有效期达到限制后会重新触发审批。
为兼容 Nextcloud 32 当前部署方式，`info.xml` 版本号保持 `0.5.9`，不要单独修改版本号，避免触发整站更新页面。

16. 常见问题
16.1 为什么分享时提示像是失败？
命中审批规则后，插件会主动阻断原始分享创建。Nextcloud 原生分享接口可能会以错误提示形式展示审批提示，这是预期行为。
只要提示内容类似：
```text
分享申请已提交审批，审批通过后文件才会真正分享。
```
就表示已经进入审批流程。
16.2 为什么审批通过后才看到分享？
这是插件的核心设计：审批前不允许文件真正流出，审批通过后才由插件恢复创建分享。
16.3 为什么下载审批通过后还要重新点击下载？
下载请求在审批前已经被中断，审批通过后系统只是创建下载授权，不会自动续接原来的下载请求。用户需要重新点击下载，系统会按授权次数和有效期放行。
16.4 为什么下载次数用完后又要审批？
下载审批的授权是有次数限制的。审批人设置的允许次数用完后，再次下载会重新进入审批流程。
16.5 为什么超过有效期后又要审批？
下载授权只在审批人设置的有效期内生效。超过有效期后，为了安全合规，需要重新发起下载审批。
16.6 为什么 30 秒内重复点击没有重复通知？
这是防重复申请机制，用于避免用户连续点击导致审批人收到大量重复通知。
16.7 为什么客户端通知点击会打开浏览器？
不同 Nextcloud 客户端对通知 action 的支持不完全一致。为了保证桌面端和移动端都能完成审批，本版本对客户端通知采用浏览器 fallback 方式处理审批。
16.8 原 Webhook 功能还能用吗？
可以。本版本是增量开发，不影响原有 Webhook 功能。
